# Backup Plan

**Use when:** installations fail, internet is unreliable, or model downloads are too slow.

If a live environment issue occurs:

| Problem | Backup response |
| --- | --- |
| Many installations fail | Use one projected instructor machine |
| Some installations fail | Pair participants with working setups |
| Internet is slow | Skip live model downloads and discuss prepared output conceptually |
| JupyterLab fails | Read notebooks as static documents and narrate expected output |
| Time runs short | Preserve corpus interpretation and final reflection |

## Alternative activities

- Read and discuss glossary terms together.
- Compare how a raw Arabic sample differs from cleaned text.
- Ask participants to annotate one printed Arabic sample: what would be easy or difficult for a computer to count?
- Ask participants to write short reflection answers to the prompts in `05_bias_power_and_reflection.ipynb`.

## Minimum Viable Workshop

If most installations fail, the workshop can still meet its introductory goals:

1. Instructor opens the notebooks on one projected machine.
2. Participants read the markdown cells and predict code output.
3. Instructor runs cells and pauses for interpretation.
4. Participants complete the reflection exercise on paper or in a shared document.

> **Teaching note:** the backup workshop is still a methods workshop. The core learning goal is understanding the workflow and its limits, not proving that every laptop can run every package.
